# 测试验证文档 (Testing Strategy)

鉴于这是一个 MVP 项目，我们优先进行端到端 (E2E) 级别的核心链路测试，以及 RAG 功能的准确率测试。

## 1. 基础设施连通性测试
- **TiDB 连通测试**：确认 Next.js 能否通过 MySQL 驱动成功连接 TiDB，并且 Vector 数据类型的存取是否正常。
- **大模型 API 连通测试**：确认能够正常调用指定的 LLM (如通义千问) 及其对应的 Embedding 模型。

## 2. 核心链路测试 (手动 / UI)

### 2.1 知识库录入测试
- 在 `/admin` 页面输入一段虚构的产品信息（例如：“我们的智能保温杯的保修期为 36 个月”）。
- 提交后，验证数据库的 `knowledge_chunks` 表中是否成功生成并插入了文本及对应的 Vector 向量。

### 2.2 RAG 智能问答测试
- 在主界面发送相关问题（例如：“你们的杯子保修多久？”）。
- **预期结果**：AI 能够准确回复“保修期为 36 个月”。
- 发送不相关的问题。
- **预期结果**：AI 触发 Fallback 机制，告知无法回答该领域的问题并提示转接人工。

### 2.3 跨端无缝接力测试
- 在 PC 浏览器开启对话，发送两轮消息。
- 点击“手机端继续”，扫描生成的二维码。
- **预期结果**：手机浏览器打开同样的页面，并且能看到刚才在 PC 上的两轮聊天记录。手机端发送新消息后，PC 端如果刷新，也能看到最新记录（或者仅作单向接力演示，根据实际实现复杂度而定）。

## 3. UI/UX 测试
- 使用 Chrome DevTools 模拟多终端尺寸 (iPhone, iPad, Desktop)。
- 检查深色/浅色模式切换时，毛玻璃和按钮高亮是否有视觉瑕疵。
- 确认流式文字输出时，滚动条能自动定位到底部。
