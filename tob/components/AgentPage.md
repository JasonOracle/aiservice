# AgentPage 坐席监控组件

## 💡 核心思想
AgentPage 是 B 端智能客服系统的中枢调度界面，基于 Ant Design X 构建。其核心设计包括：

1. **真实会话流与多会话隔离**：会话列表与聊天记录均来自后端持久化
   （`GET /api/conversations`、`GET /api/conversations/{id}/messages`），按「**客户 × 店铺 × 商品**」
   维度组织 —— 同一客户在多家店铺的咨询各自独立成条，列表标题为「店铺名 · 客户名」，
   副标题为「商品名 · 最后一条消息」；通过 WebSocket (`/ws/agent`) 实时接收 C 端提问、AI 回复
   与人工接入请求，并按 `conversation_id` 归集到对应会话。
   > 2026-09-12 订正：原文为「通过 `/api/users` 加载种子用户列表、按 `user_id` 在前端独立维护消息池」，
   > 该实现已废弃 —— 消息现由后端 `messages` 表承载，前端仅做展示与本地缓存，故刷新与重启后历史不丢。

2. **双层 AI 托管状态仲裁（已真正生效）**：
   - 提供「全局全部 AI 托管总开关」作为基准策略；
   - 每个**会话**顶部具备独立的「会话级专属 AI 托管 Switch」；
   - 仲裁逻辑：会话级设置优先于全局；会话未单独设置（`ai_managed = NULL`）时回落全局；
   - **状态读写后端**（`GET/PUT /api/ai-custody`）并持久化，**关闭后后端不再生成 AI 回复**；
     刷新页面、重启服务均不丢，多坐席浏览器之间通过 `ai_custody` 广播实时同步。
   > 2026-09-12 订正：原文为「按用户维护会话级 Switch」，且当时状态仅存于前端 `useState`
   > （关闭不生效、刷新会自行弹回）。现已改为后端持久化的会话级开关。

3. **主流 SaaS 视觉设计规范**：采用 Ant Design 经典浅灰底色（`#f0f2f5`）与纯白卡片容器体系，配合**品牌主色橙（`#FF6A00`）**渐变看板，彻底告别沉重暗色。
   > 2026-09-12 订正：主色已由 antd 蓝 `#1677ff` 统一为品牌橙 `#FF6A00`，与 C 端商城一致。

4. **「请求人工接入」告警**（2026-09-12 新增）：接收后端广播的 `handoff_request` 消息后，
   弹通知告警 + 会话列表打红色「待接入」Tag + 自动切到该会话 + 在消息流插入 system 提示条 +
   **自动关闭该会话的 AI 托管**。触发来源有两种，后端统一判定（`backend/handoff.py`）：
   - `reason = "user"`：用户主动要求人工（如「我要人工客服」）；
   - `reason = "ai_fallback"`：AI 检索不到知识库、按高压线兜底提示「请转人工」。

   > 判定的关键词**刻意不含裸词「人工」**，避免「人工智能」「人工湖」等词误触发。

5. **快捷短语**（2026-09-12 新增，交互参考千牛）：人工输入框**正上方**提供一排常用话术胶囊按钮，
   内置 8 条（`QUICK_PHRASES` 常量），覆盖 **问候 → 处理中 → 售后 → 收尾** 四阶段服务流程。
   - **只填入、不发送**：单击把话术写入输入框；若已有草稿则**换行追加**（不覆盖坐席已输入内容），
     随后 `focus({ cursor: "end" })` 把光标落到末尾，方便接着补字；
   - 未选中会话时整排**置灰禁用**，与输入框状态保持一致；
   - 样式：浅橙底 `#FFF7F1` + 橙字 `#E8480A` + 边框 `#FFE0C7`，hover 升为底 `#FFEFE4` / 边 `#FF6A00`；
   - 若需支持坐席自定义短语，把 `QUICK_PHRASES` 换成后端下发的配置即可。

## 💻 使用示例
```tsx
import AgentPage from "@/components/AgentPage";

export default function AdminConsole() {
  return (
    <div style={{ padding: 24, background: "#f0f2f5" }}>
      <AgentPage />
    </div>
  );
}
```
